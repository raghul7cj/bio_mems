## 2. Physics the detector relies on (short version, for the TA meeting)

Washburn: L² = K·t, so the time to fill the segment between electrodes i−1 and i is

  Δt_i = (L_i² − L_{i−1}²) / K  ≡  E_i   (expected segment time, a per-electrode constant)

Define the **segment ratio** ρ_i = Δt_i,obs / E_i. Every fault class from H§3.4 leaves a different pattern in the vector ρ = (ρ_1 … ρ_N):

| Pattern in ρ | Physical reading | Class |
|---|---|---|
| all ρ_i ≈ 1 | nominal K | NOMINAL |
| all ρ_i ≈ r ≠ 1, mutually consistent | K changed everywhere (μ, γ, θ, or pore radius) | UNIFORM_K (slow/fast). *Which property: not identifiable* |
| ρ_1 … ρ_{j−1} ≈ 1, ρ_j clearly > 1 | Extra hydraulic resistance appears in gap j | RESTRICTION, location = gap j |
| electrode j+1 never fires within its adaptive window | front stopped (sample exhausted) | STALL, location = gap j |
| timestamps non-monotonic, an electrode fires before arming, or one is missing while a downstream one fires | physically impossible | SENSOR_FAULT, electrode index |

Why segment ratios rather than absolute times: in a series-resistance (Darcy) picture a restriction in gap j only changes the increments from j onward, so the *first* anomalous increment locates it. A restriction upstream of electrode 1 raises ρ_1 already, and is reported as UNIFORM_K. This is the stated limitation in H§3.4. The generator does model it, so the report can show *how often* that confusion actually happens, rather than just asserting it.

## 3. Architecture options and the choice

### Option A1 — Fixed absolute windows (simplest)
Precompute [t_lo,i , t_hi,i] per electrode from a nominal K. The RTL is a counter and comparators only, with no multiplier.
- **+** Tiny, trivially verifiable.
- **−** It detects but barely classifies. A slower fluid violates every window, so it looks the same as a restriction followed by its knock-on effects. It also rejects legitimate strip-to-strip K variation unless the windows are wide, which costs missed detections.

### Option A2 — Segment-ratio classifier with online K̂ (**recommended**)
Interface A (digital arrival events). From the first segment the block estimates r̂ = ρ_1 and tests each later segment for consistency with r̂ **by cross-multiplication**:

  |Δt_i · E_1 − Δt_1 · E_i| ≤ tol · Δt_1 · E_i      (no divider)

plus an absolute check of ρ_1 against [1−tol_abs, 1+tol_abs] for the NOMINAL vs UNIFORM_K decision. The stall timeout for stage i+1 is *adaptive*: t_i + r̂ · E_{i+1} · (1 + tol_stall). That adaptive, model-derived window is what separates this method from the fixed-timeout baseline (H§5.3 item 4).
- **+** Classifies all the identifiable classes, tolerates unknown fluids, and needs only one time-multiplexed multiplier (two DSP48s at the 24-bit width).
- **−** It needs a small sequencer for the multiplies, and tolerances must be calibrated against noise (see §5).

### Option B — Sampled-signal front end (add-on, not a replacement)
Ingest the sampled electrode current per channel and detect the wetting step on-chip (threshold + hysteresis, or a matched step detector). It sits in front of A2 and produces the same arrival events.
- **+** Lets the RTL run on the real traces from `data_P3.csv`.
- **−** More front-end design, and the vertical-flow data validate only event detection, not the lateral model.

**Choice:** build A2 on interface A. Keep A1 as a *Python* baseline-like ablation if time allows. B is optional in Phase 6 (open question 5).

### RTL block diagram (A2)
```
arrive[N-1:0] ─► sync2 ─► debounce(D ticks) ─► rise-edge ─┐
                                                          ▼
tick_gen (1 ms) ─► timestamp ctr (24 b) ─────► capture regs t_i, Δt_i
                                                          │
                     const ROM: E_i, tol (Q-format) ──► MAC sequencer (1 mult, time-shared)
                                                          │ residual flags per segment
arm ─► flow FSM: IDLE → ARMED → WAIT(i) … → CLASSIFY → REPORT
                     │ adaptive per-stage timeout
                     ▼
               result regs: valid, class[2:0], loc[2:0], r̂ (debug)
               (AXI-Lite wrapper only if Phase 7 happens)
```
**Bit widths (to be justified in the report).** Tick = 1 ms. Worst-case run = slow fluid (r up to ~5) × nominal fill (~200–400 s, *assumed until Phase 2*) plus the stall margin, under 2 h, so 23 bits are needed and **24-bit timestamps** are used; a wrap before REPORT is flagged. E_i: 24 bits unsigned. Tolerances: Q1.8. Products: 48 bits. All rounding is truncation, mirrored exactly in the fixed-point Python reference.

## 4. Models and verification chain

```
generator (rich Darcy model, seeds) ─► corpus/*.csv ─┬─► golden_float.py ──► metrics vs ground truth
                                                     ├─► golden_fixed.py ──► expected.csv
                                                     ├─► baselines.py (fixed timeout, single sensor)
                                                     └─► xsim tb (reads stimulus) ─► rtl_out.csv
                                         compare.py: rtl_out == expected (bit-exact, 100 %)
```
- **Generator ≠ detector.** Quasi-steady Darcy flow through piecewise segments, so the front speed is set by the capillary pressure over the integrated resistance of the wetted length. It adds a finite source volume (stall), fluid-property scaling of K, strip-to-strip K variability, and sensor effects (Gaussian jitter, a systematic detection lag [cf. 1.8 s in Bezinge SI], missed, spurious and stuck electrodes). Bosanquet inertia and evaporation are optional extras that come last.
- **Golden independence.** `golden_float.py` is written from §2 of this plan, not from the RTL. `golden_fixed.py` re-implements the same spec in integer arithmetic with the RTL's widths. Float-vs-fixed agreement is reported separately.
- **Testbench.** Plain SystemVerilog, file-driven, under xsim. One simulation runs the whole corpus (reset between scenarios) and writes one result line per scenario.
- **SVA** (bound to the FSM): legal transitions only; exactly one `valid` per run; no `valid` before the last arrival or its timeout; captured timestamps monotonic within a run.
- **Coverage.** Covergroups on FSM state and transition, class, location, and the boundary bins. `xcrg` produces the report.
- **Boundary cases.** Arrival exactly at a window edge (±1 tick), back-to-back arrivals in the same tick, an arrival before `arm`, a glitch shorter than the debounce, and counter wrap.
- **Threshold calibration without overfitting.** Tolerances are tuned on a *calibration* seed set to a target false-alarm rate (e.g. 5 %), then all metrics are reported on held-out seeds. The baselines get the same treatment.
